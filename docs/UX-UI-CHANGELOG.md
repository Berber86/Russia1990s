# UX/UI: что исправлено

Реализация плана из `UX-UI-AUDIT.md`. Все пять этапов выполнены.
Файлы: `index.html`, `style.css`, `app.js`. Логика игры, промпты и работа
с LLM не затронуты — менялись только интерфейс и подача.

---

## Этап 1 — Починить сломанное

**Семантические токены.** `--danger`, `--warning`, `--success`, `--accent`,
`--link`, `--bg` использовались в 10 местах, но нигде не объявлялись. Теперь
объявлены в обеих темах и привязаны к палитре. Починились: кнопка «Повторить
ход», кнопка «Начать новую жизнь» на game over, заголовок эпилога, блок
«Полировка сорвалась». Алиасы (`--muted`, `--border`, `--surface-*`) сведены
в один блок — раньше дублировались.

**Контраст светлой темы.** Пересчитан по WCAG AA на всех текстовых
подложках:

| Токен | Было | Стало |
|---|---|---|
| `--amber` на `paper-2` | 2.96 : 1 | **4.76 : 1** |
| `--ink-dim` на `paper-2` | 3.48 : 1 | **4.85 : 1** |
| `--ink-muted` на `paper-2` | 1.95 : 1 | **4.52 : 1** |
| текст `.primary` | 3.95 : 1 | **6.61 : 1** |

**Прочее:** убран дубль атрибута `class` у `#region-select-row` (из-за него
до инициализации JS были видны оба селектора); проставлены `for`/`id`;
`:focus-visible` расширен на `.option-btn`, `.choice-btn`, `.archive-btn`
и степпер; все `100vh` получили парный фолбэк `100dvh`.

## Этап 2 — Ожидание и обратная связь

**Блокирующий оверлей убран.** Полноэкранный `retro-loader-overlay`
(`z-index: 99999`, `pointer-events: all`) удалён вместе со стилями. Вместо
него — инлайновый блок: текст истории остаётся читаемым.

**Мёртвый `#loader` починен.** Он переключался через `style.display`, а в
разметке висел класс `.is-hidden` с `!important` — элемент не появлялся
никогда. Теперь управление идёт через класс.

**Этапы генерации.** Три шага — «Пишу сцену» → «Обдумываю последствия» →
«Готовлю варианты» — с отметкой пройденных. Тексты уже были в коде, их просто
не было видно.

**Скелетон** на месте будущих вариантов выбора вместо крутилки.

**Отмена хода.** `AbortController` протянут через `callLLM` во все три ветки
fetch. Пауза backoff между повторами тоже прерываемая — иначе кнопка не
срабатывала во время ожидания. Отмена не считается ошибкой: интерфейс
возвращается к прежним вариантам.

**Тосты вместо `alert()`.** Все 7 системных диалогов заменены на тосты в
стилистике продукта: `role="status"`, автоскрытие, максимум 3 в стопке,
закрытие по клику.

**Человеческие ошибки.** `describeTurnError()` переводит технические ответы
API в понятные формулировки — отдельно 401, 429, таймаут, 5xx. Технические
подробности спрятаны в `<details>`.

## Этап 3 — Онбординг

- Шаг «Пролог» (экран без единого действия) убран, его текст перенесён в
  showcase-колонку. Мастер: **7 экранов → 4 шага**, и счётчик наконец
  совпадает с реальностью.
- Полоса прогресса заменена **кликабельным степпером**: видно все шаги,
  к пройденному можно вернуться за один клик.
- Починена сквозная нумерация секций: `counter-reset` перенесён с
  `.setup-wizard` на `.setup-step`. Раньше на шаге 3 из 4 секции были
  пронумерованы «05» и «06».
- Мобильный hero: было `padding-top: 56vw` + картинка `60vw` + лид +
  4 карточки (~1.5 экрана до первого поля). Стало `30vh` + свёрнутые
  под маску карточки.
- `.setup-showcase` с `min-height: 880px` → `min(780px, 100dvh - отступы)`:
  на ноутбуке 1366×768 экран больше не обрезается.

## Этап 4 — Игровой экран

- **Хоткеи 1-9** на варианты выбора с видимыми подсказками-цифрами
  (скрыты на сенсорных экранах через `@media (hover: none)`). Стрелки
  влево/вправо листают архив. Хоткеи не перехватывают ввод в полях и
  не срабатывают при открытых оверлеях.
- **Focus trap** (`trapFocus`/`releaseFocus`) для всех оверлеев: настройки,
  lore-панели, подтверждение сброса, dev-модалки. Фокус возвращается на
  элемент-инициатор при закрытии.
- **Блокировка скролла** через счётчик `lockScroll`/`unlockScroll` —
  корректно работает при вложенных оверлеях. `.lore-panel` раньше вообще
  не блокировала фон.
- **Архивная лента**: `← ● ⧉ →` заменены на иконки из спрайта, добавлен
  **выпадающий список периодов** («Зима 1993 · 7 лет · ход 1 из 3») —
  прыжок к любому ходу вместо перелистывания по одному.
- Дублирующее копирование убрано: было в трёх местах, осталось в сайдбаре.
- Скролл после хода — к началу сцены, а не к верху документа.

## Этап 5 — Техдолг

- **Медиа-запросы:** 11 разрозненных блоков → **7 уникальных брейкпоинтов**
  в одном разделе в конце файла. Было: `480px` трижды, `700px` и `1080px`
  дважды.
- **Инлайновые стили:** в HTML — с 30+ до **0**; в JS осталось 3 (реально
  динамические значения: ширина шкалы, задержка каскада).
- **Dev-панели** переведены на токены — в светлой теме больше не остаются
  тёмными. Кнопки собраны в док, эмодзи заменены иконками спрайта.
- Удалены дубли: `.dev-tool-fab` (3 объявления с конфликтующим
  `!important`), `.option-btn` (`min-height` 48 vs 52), пустое правило
  `.settings-tab-panel { }`, мёртвые ссылки `npcs-display`/`inventory-display`.
- Каскад абзацев истории — формулой `sibling-index()` с `@supports`-фолбэком.
  Раньше 9 ручных правил, и все абзацы с 10-го появлялись разом.
- **Иконки:** добавлены `arrow-left`, `arrow-right`, `close`, `check`,
  `alert`, `moon`, `sun`. Из интерфейса убраны `✕ ◐ ◑ ● ⧉ ♂ ♀ 🐞 🔬 ✅ ❌ ⚠️ ✦`.
- **Семантика и мета:** `<main>`, `<header>`, `<nav>`, `h1` на игровом экране,
  `description`, Open Graph, `theme-color` для обеих тем, SVG-favicon.
- `role="radiogroup"` + `aria-checked` для всех групп выбора — состояние
  теперь передаётся скринридеру, а не только цветом.
- `innerText` → `textContent` (без принудительного reflow).

## Проверка

Браузерный движок в песочнице недоступен, поэтому проверка выполнена
DOM-тестами на jsdom с реальными `index.html` + `constants.js` + `app.js`:

- прохождение мастера вперёд/назад, переходы по степперу, состояния шагов;
- синхронизация `aria-checked`, переключение регион/город;
- рендер игрового экрана, хоткеи, архивный список и переключение периодов;
- этапы загрузки, скелетон, блокировка кнопок, отмена хода;
- тосты (типы, лимит стопки), классификация ошибок;
- focus trap, Escape, счётчик блокировки скролла;
- вычисление токенов в обеих темах, показ dev-панелей по флагу.

Во всех сценариях — 0 ошибок в консоли. `node --check` на `app.js` проходит,
скобочный баланс CSS сходится (634/634).
