# UX/UI аудит «Эпоха Перемен»

Дата: 15.08.2026 · Ветка: `arena/01a00700-russia1990s`
Объём проверки: `index.html` (611 строк), `style.css` (2949), `app.js` (3820).

Продукт хороший: атмосфера, типографика (EB Garamond + JetBrains Mono),
VHS-слои, две темы. Проблемы — не в стиле, а в **накопившемся техдолге слоёв
правок** (три «STAGE»-блока, дублирующие друг друга) и в **обратной связи
интерфейса**: игрок часто не понимает, что происходит и что будет дальше.

Ниже — найденные дефекты, сгруппированы по приоритету. У каждого есть ссылка
на место в коде и предлагаемое решение.

---

## P0 — Критично: ломает восприятие или блокирует пользователя

### 1. Половина цветовых токенов не существует — фолбэк в «невидимое»

В коде используются `var(--danger)`, `var(--warning)`, `var(--accent)`,
`var(--link)`, `var(--bg)`. Ни один из них **не объявлен** ни в `:root`,
ни в `body[data-theme="paper"]`.

| Место | Код | Что реально видит игрок |
|---|---|---|
| `app.js:2553` | `btn.style.borderColor = 'var(--warning)'` | Кнопка «Повторить ход» после ошибки — **без рамки** |
| `app.js:3007` | `btn.style.borderColor = 'var(--danger)'` | Кнопка «Начать новую жизнь» на game over — **без рамки** |
| `app.js:633-636` | блок «Полировка сорвалась» | Заголовок и кнопка — **невидимый цвет текста** |
| `app.js:717` | `<h2 style="color:var(--accent)">Эпилог</h2>` | Заголовок эпилога — **без цвета** |
| `app.js:652` | `border: 1px dashed var(--link)` | Кнопка «Отполировать текст» — **без рамки** |
| `style.css:2140` | `.illustration-btn:hover { color: var(--bg) }` | Текст на ховере — **сливается** |

То есть **самые важные состояния — ошибка, смерть героя, финал — визуально
не оформлены вообще.**

**Решение:** объявить семантические токены в обеих темах и заменить инлайновые
стили на классы `.choice-btn--danger`, `.choice-btn--retry`.

```css
:root {
    --danger:  var(--rust);
    --warning: var(--amber);
    --success: var(--moss);
    --accent:  var(--amber);
    --link:    var(--amber);
    --bg:      var(--paper-0);
}
```

### 2. Два конкурирующих индикатора загрузки, один из них сломан

- `#loader` (`index.html:448`) управляется через `.is-hidden` в разметке,
  но `setLoading()` (`app.js:976`) переключает его через `style.display`.
  Класс `.is-hidden` имеет `!important` (`style.css:2949`) → **элемент никогда
  не появляется**. Вся полоска `.loading-bar` и `#loader-message` — мёртвый код.
- Реально показывается `.retro-loader-overlay` — **полноэкранный блокирующий
  оверлей** с `z-index: 99999` и `pointer-events: all`.

**Проблема UX:** ход у LLM длится 20-60 секунд. Всё это время экран полностью
перекрыт, историю прочитать нельзя, отменить нельзя, прогресса нет — только
крутилка. Это худший из возможных паттернов ожидания для долгой операции.

**Решение:**
- Убрать блокирующий оверлей. Оставить **инлайновый** индикатор на месте блока
  выбора: текст остаётся читаемым, кнопки выбора уходят в `:disabled`
  (механика уже есть в `setLoading`).
- Показывать **этапы**: «Пишу сцену» → «Обдумываю последствия» → «Готовлю
  варианты». Тексты этапов уже есть в `app.js:2374/2426/2459`, их просто
  не видно за общей крутилкой.
- Добавить скелетон-строки вместо спиннера — ожидание воспринимается короче.
- Кнопка «Отменить ход» (AbortController) для зависших запросов.

### 3. `window.alert()` для успеха и ошибок — 7 мест

`app.js:967, 970, 3149, 3152, 3177, 3180, 3531`

```js
alert('✅ Период скопирован!');
alert('❌ Не удалось скопировать период.');
```

Системный модальный диалог полностью выбивает из атмосферы 90-х, требует
лишнего клика и на мобильных перекрывает экран.

**Решение:** тост-компонент в стилистике продукта (JetBrains Mono, янтарь,
2.5 сек, `role="status"`, авто-скрытие). ~30 строк CSS + 15 строк JS.

### 4. Контраст в светлой теме «paper» ниже нормы WCAG

Расчёт по фактическим токенам:

| Пара | Контраст | Норма |
|---|---|---|
| `--amber` `#b46a1f` на `--paper-0` | **3.5 : 1** | нужно 4.5 |
| `--amber` на `--paper-2` | **2.96 : 1** | нужно 4.5 |
| `--ink-dim` `#7a6f5f` на `--paper-2` | **3.48 : 1** | нужно 4.5 |
| `--ink-muted` на любом фоне | **1.7–2.3 : 1** | провал |
| Текст `#fff8e7` на кнопке `.primary` | **3.95 : 1** | нужно 4.5 |

`--amber` — это **основной акцент**: eyebrow-надписи, «ЧТО ТЫ СДЕЛАЕШЬ?»,
номера шагов, ссылки. В светлой теме всё это читается плохо.

**Решение:** затемнить акценты светлой темы до `--amber: #8d4f12`,
`--ink-dim: #665c4c`, `--ink-muted: #857a68`; на `.primary` в paper-теме
использовать `#fffdf7`. Правка ~6 строк, визуально почти незаметна,
но проходит AA.

## P1 — Серьёзно: мешает пользоваться

### 5. Мастер создания героя: 7 экранов при заявленных «5 шагах»

`index.html:141-303` содержит **7** секций `data-step`, а `SETUP_STEPS`
(`app.js:116`) описывает **5**. Группировка сделана через `data-wizard-group`,
но:

- Счётчик `.setup-section h3::before` использует `counter(section)`
  (`style.css:578`) со сквозным инкрементом по всем 7 секциям, включая
  скрытые. На шаге «Ритм» игрок видит номера **05** и **06**, а сверху
  написано «Шаг 4 из 5». Нумерация противоречит сама себе.
- Шаг «Пролог» — это экран **только с текстом**, без единого действия.
  Он существует, чтобы кнопка называлась «Начать» (`app.js:843`).
  Это лишний клик до первого осмысленного выбора.
- Валидации нет: «Дальше» всегда активна, назад с последнего шага —
  тоже (кнопка «Дальше» просто скрывается, `app.js:842`).

**Решение:**
- Убрать шаг «Пролог», перенести его текст в левую showcase-колонку
  (там уже есть лид и 3 фичи — они дублируют пролог по смыслу).
- Сделать **4 шага**: Герой → Место → Ритм → Старт.
- Прогресс-полосу заменить на **кликабельные степперы** (можно вернуться
  к любому пройденному шагу за один клик, сейчас — только «Назад» по одному).
- Счётчик секций перезапускать на каждом шаге (`counter-reset` на
  `.setup-step`, а не на `.setup-wizard`).

### 6. Дубль атрибута `class` — регион не скрывается на первой отрисовке

`index.html:209`:

```html
<div class="setup-row" id="region-select-row" class="is-hidden">
```

Второй `class` браузером **игнорируется**. Скрытие работает только потому,
что `updateLocationDescription()` (`app.js:1349`) позже ставит
`style.display`. До инициализации JS видны **оба** селектора — «Регион»
и «Город» одновременно.

**Решение:** удалить лишний атрибут, перевести показ/скрытие на класс
`.is-hidden` вместо инлайнового `style.display` (сейчас в коде смешаны
три механизма скрытия: `.hidden`, `.is-hidden`, `style.display`).

### 7. Ни у одного `<label>` нет `for`

7 меток в форме (`index.html`), связанных — **0**. Клик по слову «Возраст:»
не фокусирует селект, скринридер не озвучивает подпись поля.
Аналогично `#api-key` и `#start-age`.

**Решение:** проставить `for` / `id` — 7 строк.
Для групп кнопок (`#gender-btns`, `#location-type-btns`, `#pace-btns`)
использовать `role="radiogroup"` + `aria-checked` вместо `.selected`:
сейчас выбранное состояние **вообще не передаётся** скринридеру, только
цветом и псевдоэлементом `::after` с галочкой (`style.css:2779`).

### 8. Клавиатура: выборы недоступны с цифр, модалки без фокус-ловушки

- В текстовой RPG варианты выбора естественно выбирать клавишами **1-4**.
  Обработчика нет.
- В `.settings-modal`, `.lore-panel`, `.confirm-modal` есть Escape
  (`app.js:911, 1056, 2873`), но **нет focus trap** — Tab уводит фокус на
  элементы под оверлеем.
- `.lore-panel` не блокирует скролл body (в отличие от `app.js:2858`, где
  для иллюстраций это сделано) — фон прокручивается под открытой панелью.

**Решение:** общий хелпер `trapFocus(el)` + `lockScroll()`, применить ко всем
трём типам оверлеев. Хоткеи 1-4 на выбор, с подсказкой-цифрой в углу
`.choice-btn`.

### 9. Архивная лента: непонятные символы вместо смысла

`index.html:437-441` — четыре кнопки: `←`, `●`, `⧉`, `→`.
`●` = «вернуться к текущему», `⧉` = «копировать». Понять невозможно,
`aria-label` есть, но визуальной подсказки нет. В проекте уже собран
**спрайт из 40 иконок** (`#icon-copy`, `#icon-refresh`, `#icon-pin`) —
здесь он не используется.

**Решение:** заменить на иконки из спрайта + `title`. Ленту сделать
информативной: `Зима 1993 · 8 лет · ход 4 из 12` вместо текущего
`Текущий период`. Ещё лучше — выпадающий список периодов для прыжка
к любому ходу (сейчас перелистывание строго по одному).

### 10. Копирование продублировано в трёх местах

`⧉` в архивной ленте (`index.html:440`), «Период» и «Вся история» в сайдбаре
(`index.html:490-491`) — одна и та же функция
`copyArchiveEntryToClipboard`. Три разных визуальных представления одного
действия.

**Решение:** оставить один блок «Экспорт» в сайдбаре, убрать `⧉` из ленты.

## P2 — Полировка и техдолг

### 11. CSS: 3 слоя переопределений, дубли правил

Файл разбит на исторические слои: базовые стили → `STAGE 2 — ИГРОВОЙ ЭКРАН`
(строка 2445) → `STAGE 4 — ФИНАЛЬНАЯ ДОСТУПНОСТЬ` (2742). Следствия:

- `.dev-tool-fab { display: none !important }` объявлено **дважды**
  (2426 и 2599).
- `@media (max-width: 1080px)` с идентичным содержимым — **дважды**
  (2002 и 2670).
- `@media (max-width: 700px)` — дважды (2016, 2662),
  `@media (max-width: 480px)` — трижды (2076, 2797, 2943).
- `.option-btn` определён дважды подряд (675 и 2782) — второй только ради
  `min-height: 52px`, перебивая `48px` из первого.
- `.choice-btn` — три определения (1400, 2502, 2812).
- `.settings-tab-panel { }` — пустое правило (2420).

Итог: чтобы понять итоговый вид кнопки, нужно держать в голове 3 места.
Любая правка рискует не примениться.

**Решение:** схлопнуть слои — один блок токенов, один набор компонентов,
**один** набор медиа-запросов в конце файла. Ожидаемое сокращение ~15-20%
объёма без изменения внешнего вида.

### 12. Инлайновые стили в HTML и JS вместо классов

`index.html:539-608` — модалки debug и prompt-inspector написаны целиком
на `style="..."`, включая цвета-хардкоды `#c98a3a`, `#26201a`, `#0c0a08`,
которые **не переключаются вместе с темой**. В светлой теме инспектор
промпта остаётся тёмным.

Аналогично `app.js:154-156, 633-636, 684, 717`.

**Решение:** вынести в CSS-классы, использовать токены.

### 13. Единый стиль иконок нарушен

Собран монохромный SVG-спрайт (40 символов, `index.html:27-68`) — отличное
решение. Но параллельно в интерфейсе живут:

- эмодзи `🐞` и `🔬` на dev-кнопках (`index.html:596, 599`),
- `⚠️` в сообщении о полировке (`app.js:634`),
- `✅` / `❌` в алертах,
- `✦` в кнопке полировки (`app.js:652`),
- символы `◐` / `◑` в переключателе темы,
- `♂` / `♀` в выборе пола (`index.html:163-164`),
- `←`, `●`, `⧉`, `→`, `✕`, `↺` в архиве и модалках.

**Решение:** всё, что видит игрок, — из спрайта. Эмодзи допустимы только
в dev-инструментах.

### 14. Мобильная версия: hero-картинка съедает первый экран

`style.css:2016-2075`: на `≤700px` showcase получает `padding-top: 56vw`
и картинку `height: 60vw`, плюс лид, плюс 3 фича-карточки в столбик.
До первого поля формы — примерно **полтора экрана скролла**. При этом
`order: 1` ставит showcase **над** формой.

**Решение:** на мобильных дать компактный hero (~30vh), фича-карточки
свернуть в аккордеон или показывать только на шаге «Пролог»/showcase,
форму поднять выше. Показывать `100dvh` вместо `100vh` (сейчас 14 мест
с `100vh` — на iOS Safari это даёт обрезание нижней части оверлеев
адресной строкой).

## Что предлагаю сделать — план по этапам

Каждый этап самостоятелен, даёт видимый результат и не ломает предыдущий.

### Этап 1 — «Починить сломанное» (быстро, высокий эффект)
1. Объявить недостающие токены `--danger/--warning/--accent/--link/--bg/--success`.
2. Поднять контраст светлой темы до WCAG AA.
3. Убрать дубль `class` в `#region-select-row`.
4. Проставить `for`/`id` у всех меток.
5. Расширить `:focus-visible` на `.option-btn` и `.choice-btn`.
6. `100vh` → `100dvh` для оверлеев.

### Этап 2 — «Ожидание и обратная связь» (главный UX-выигрыш)
1. Убрать блокирующий `retro-loader-overlay`, сделать инлайновое ожидание
   со скелетоном на месте выборов.
2. Показывать этапы генерации (тексты уже написаны).
3. Кнопка «Отменить ход».
4. Заменить 7 `alert()` на тосты в стилистике продукта.
5. Оформить состояния ошибки/game over/эпилога нормальными классами.

### Этап 3 — «Онбординг» (мастер создания героя)
1. Убрать шаг «Пролог», свести к 4 шагам.
2. Кликабельный степпер вместо полосы прогресса.
3. Починить сквозную нумерацию секций.
4. Мобильный hero — компактный, форма выше.

### Этап 4 — «Игровой экран»
1. Хоткеи 1-4 на варианты выбора + визуальные подсказки.
2. Focus trap и блокировка скролла для всех оверлеев.
3. Архивная лента: иконки из спрайта, информативная подпись,
   выпадающий переход к любому периоду.
4. Убрать дублирующее копирование.

### Этап 5 — «Техдолг CSS/иконки»
1. Схлопнуть 3 слоя стилей, свести медиа-запросы в один блок.
2. Инлайновые стили → классы + токены (в т.ч. dev-модалки под темы).
3. Все пользовательские иконки — из спрайта.
4. Мета-теги, семантика (`<main>`, `<header>`, h1 на игровом экране).

## Оценка

| Этап | Файлы | Риск | Эффект |
|---|---|---|---|
| 1 | `style.css`, `index.html` | минимальный | средний |
| 2 | `app.js`, `style.css` | средний | **высокий** |
| 3 | `index.html`, `app.js`, `style.css` | средний | высокий |
| 4 | `app.js`, `style.css` | низкий | средний |
| 5 | `style.css` (рефакторинг) | средний | долгосрочный |

Рекомендую начать с этапов **1 + 2** — это чинит всё, что сейчас реально
сломано, и радикально меняет ощущение от главного сценария (ожидание хода).
